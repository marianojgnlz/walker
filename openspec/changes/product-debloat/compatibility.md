# Compatibility boundaries — Product Debloat

## Authentication API (U01.a.001)

The public `vscode.authentication` namespace remains available as an inert compatibility surface in both Node and worker extension hosts. The shared API factory implements:

| Operation | Retained behavior |
| --- | --- |
| `getSession` without truthy `createIfNone` or `forceNewSession` | Resolves `undefined`, including silent, challenge, and authorization-server inspection. |
| `getAccounts` | Resolves an empty array. |
| Proposed `hasSession` | Retains the `authSession` proposal guard, then resolves `false`. |
| `onDidChangeSessions` | Uses `Event.None`; listeners receive a disposable and never fire. |
| `getSession` with truthy create/force options | Rejects with localized `AuthenticationUnsupported` / `WALKER_AUTHENTICATION_UNSUPPORTED`. |
| `registerAuthenticationProvider` | Synchronously throws the same unsupported error without subscribing to or invoking the provider. |

The `authLearnMore`, `authIssuers`, and `authSession` proposal checks remain in force where their proposed options are used. The compatibility boundary does not restore provider discovery, account state, network/authentication requests, consent UI, or account services. Existing internal authentication services/RPC remain temporarily for their not-yet-disconnected consumers; their later removal belongs to A2 and is not claimed by this leaf.

## Terminal Chat service prerequisite (U05/U07) — resolved by the wave

The U05/U07 terminal prerequisite is resolved by the U06/U07 removal wave. The `agentHostTerminalService` implementation and its `IAgentHostTerminalService` registration were deleted, so the retained terminal workbench no longer renders hidden Chat terminal tabs or drives generic tab visibility through a Chat service. The only survivor is the inert `ITerminalChatService` interface declaration in `terminal/browser/terminal.ts` (decorator plus interface, zero implementations and zero consumers); the retained `productDebloatChatIntegrations.test.ts` asserts the terminal tabbed view carries no Chat references. This declaration does not authorize restoring terminal Chat UI registrations, Chat-agent tools, Chat-owned speech sessions, or Chat settings in generic terminal code.

## Account-free browser embedder API (A2-D2.001)

`IWorkbenchConstructionOptions.authenticationProviders` was removed from `workbench/browser/web.api.ts` together with its consumer in `AuthenticationService` (environment-contributed providers). This is an intentional account-free API change: browser embedders can no longer inject authentication providers, and the web workbench no longer seeds the secret store from a server-rendered `vscode-workbench-auth-session` element. Local persisted secrets, profiles and settings are untouched — only account-login bootstrap and provider discovery are gone. The A1 public extension API facade remains the deterministic unsupported/passive-empty boundary.

## Account-free MCP and issue-reporting retained behavior (A2-D2/D3)

- **MCP servers that required OAuth now take the non-auth path.** The MCP client no longer discovers WWW-Authenticate/OAuth metadata, requests tokens, tracks sessions or replays them on session changes. Ordinary (non-auth) MCP servers keep working end-to-end; a server requiring authentication fails without token acquisition instead of prompting or signing in. The deprecated `authentication` launch property was removed end-to-end (types, validator, type converter and the `mcpToolDefinitions` proposal declaration) because it was already dead code.
- **Issue reporting is anonymous.** The reporter no longer reads GitHub sessions or pre-fills `githubAccessToken`; it always uses the unauthenticated URL/form path. This is intentional under the account-free contract.
- **A1 facade unchanged.** `createAuthenticationApiFacade` remains the deterministic unsupported/passive-empty public boundary, and `accountFreeApi.test` stays green throughout.

## MCP OAuth configuration surface disconnected (A2-D3 residual)

The MCP `oauth`/`enterpriseManaged` configuration surface was disconnected from the account/OAuth execution path as an intentional account-free change: the workbench `mcp.json` schema no longer accepts `oauth.clientId`/`oauth.enterpriseManaged`, the `mcp.enterpriseManagedAuth.idp` setting and its policy registration are gone, the "Set/Replace Client Secret" code lens and `SetOAuthClientSecret` command are removed, and `McpServerTransportHTTPOAuth` / `mcpOAuthClientSecretStorageKey` / the client-secret sanitizer no longer exist. The **neutral platform configuration normalizer and types** still recognize the `oauth.clientId` and legacy `oauthClientId` input shapes and normalize them into an inert `IMcpRemoteServerOAuthConfiguration.clientId` field (`platform/mcp/common/mcpPlatformTypes.ts`, `mcpServerConfigurationNormalizer.ts`) so existing configuration files keep parsing; no downstream reader or OAuth execution path consumes that field. Generic MCP configuration (`mcp.json` servers, headers, dev mode, collision behavior, sampling, discovery) and ordinary server start/stop/output flows are unchanged; no previously stored client-secret values are deleted from the secret store (they simply become unreachable).

## Telemetry call-site pruning — retained boundaries (U11 pass 1)

Two product-visible interface details changed intentionally while pruning call-sites; both are non-account, non-reporting and covered by focused tests:

- **`resolveMarketplaceHeaders` no longer takes service/telemetry dependencies.** Its signature is `resolveMarketplaceHeaders(version, productService)` and it returns only `X-Market-Client-Id` and `User-Agent`. The stored service-machine identifier (`getServiceMachineId`, `storage.serviceMachineId`, `<userData>/machineid`) is no longer generated, read or written — legacy values on disk are preserved and ignored. Functional gallery headers (`X-Client-Name`, `X-Client-Version`, `X-Client-Commit` in `AbstractExtensionResourceLoaderService.getExtensionGalleryRequestHeaders`) are unchanged. `extensionGalleryService.test.ts` asserts the functional headers remain and the three correlation headers (`X-Market-User-Id`, `VSCode-SessionId`, `X-Machine-Id`) are absent.
- **Remote telemetry RPC removed.** `IRemoteAgentService.updateTelemetryLevel`/`logTelemetry`/`flushTelemetry` and the `telemetry` IPC channel client are gone; `getRoundTripTime()` now uses the retained `remoteextensionsenvironment` channel. Remote connection/latency measurement behavior is unchanged from its post-U10 state (the `ping` command was already removed with the telemetry channel), and remote extension-host/workspace behavior is untouched.
- **`telemetry.feedback.enabled` is the only registered setting in the `telemetry` configuration section.** It is a retained non-telemetry setting (issue reporter, NPS survey, relauncher) and keeps its type/default/description/`EnableFeedback` policy metadata. `telemetry.telemetryLevel`, the deprecated `telemetry.enableTelemetry` and `telemetry.enableCrashReporter` are no longer registered; legacy values on disk stay untouched and inert, and no reader can enable reporting.
- **Retained no-op extension/telemetry contract unchanged:** `NullTelemetryService`/`NullTelemetryServiceShape`, the `ITelemetryService` shape (with its fixed sentinel identity fields), `TelemetryTrustedValue` and the `env.machineId`/`env.devDeviceId`/`env.sessionId` API members are deliberately untouched by this pass. `TelemetryTrustedValue` remains a public value/type marker only.
- **`disable-telemetry` argv stays accepted.** The integration runners, the smoke runner and `extensions/vscode-test-resolver` still pass it. It is recorded as a documented inert invocation-compatibility input: with no reporting service, no telemetry transport and no telemetry log output, the flag cannot turn anything on or off. Its removal is deferred to the T11 residual list rather than silently breaking those invocations.

## Telemetry call-site pruning — pass-2 retained boundaries (U11, 2026-10-06)

- **`telemetry.feedback.enabled` is registered again (regression fix).** The U11 pass-1 commit had physically deleted `platform/telemetry/common/telemetryService.ts`, which was the only registration site for this retained non-telemetry setting; every reader therefore saw `undefined` and the issue reporter, the NPS survey and the relauncher treated feedback as disabled. The registration is restored unchanged (type `boolean`, default `true`, original description and `EnableFeedback` policy metadata) and is side-effect-imported from `workbench.common.main.ts`. `productDebloat.test.ts` asserts both the registered schema/policy and the shell import, so a future module deletion cannot silently unregister it again without failing a test. The telemetry enablement settings (`telemetry.telemetryLevel`, `telemetry.enableTelemetry`, `telemetry.enableCrashReporter`) remain unregistered and cannot re-enable reporting.
- **The experiment/TAS gate is telemetry-independent.** `experimentsEnabled` (`workbench/services/assignment/common/assignmentExperiments.ts`) no longer reads `getTelemetryLevel`; it depends only on `productService.tasConfig`, the environment (`disableExperiments`, extension-test and smoke-driver flags) and `workbench.enableExperiments`. Telemetry settings can neither enable nor disable experiment fetching, and an experiment fetch is not treated as reporting.
- **The experiment client no longer receives identity.** `AssignmentFilterProvider` omits `Filters.ClientId`/`Filters.DeveloperDeviceId` (returns `null`, i.e. "not provided") instead of a placeholder identity, and the experiment client's `IExperimentationTelemetry` implementation (`AssignmentContextTracker`) keeps only the assignment-context tracking that drives refetch and `getCurrentExperiments`; its `postEvent` is deliberately inert. `addTelemetryAssignmentFilter` (public workbench API) and the `workbench.enableExperiments` setting are unchanged.
- **Retained no-op telemetry contract unchanged by pass 2.** `NullTelemetryService`/`NullTelemetryServiceShape`, the `ITelemetryService` shape with its sentinel identity fields, `TelemetryTrustedValue`, the standalone editor's `StandaloneTelemetryService` and the `env.machineId`/`env.devDeviceId`/`env.sessionId` API members stay as recorded in the pass-1 section. `disable-telemetry` remains a documented inert input.
- **`skipTelemetry` and the editor `telemetryData` widget option are inert, not removed.** Their telemetry readers (the workbench context-menu service and the platform context-view handler) are gone in this pass, so the remaining `skipTelemetry`/`telemetryData` members in `base/browser/contextmenu.ts`, `base/browser/ui/{dropdown,toolbar}`, `platform/actions/browser/{toolbar,dropdownWithPrimaryActionViewItem}` and `editor/browser/widget/codeEditor/codeEditorWidget.ts` are recorded as a T3/T2 residual for the platform-shell leaf rather than silently deleted with their producers.

## Telemetry call-site pruning — pass-5 retained boundaries (U11, 2026-10-06)

- **The `editTelemetry` subsystem is stripped, not replaced.** The contribution, the AI edit-telemetry service/arc reporter/edit-source tracking, the AI-stats status bar and their platform event shapes are queued as W44; `workbench.common.main.ts` no longer registers the contribution and `MainThreadLanguageFeatures` no longer creates suggestion ids or sends accepted/rejected AI edit events. Inline-completion `handleItemDidShow`/`handleEndOfLifetime` keep their editor-provider signatures and still forward `$handleInlineCompletion*` to the extension host.
- **Git extension `_aiEdits.*` compatibility.** `extensions/git/src/repository.ts` calls `_aiEdits.hasAiContributions` (inside a `try/catch`), `_aiEdits.clearAiContributions` and `_aiEdits.clearAllAiContributions`. With the subsystem stripped those commands are unregistered: `hasAiContributions` resolves through the catch to `false`, so `git.addAICoAuthor` never adds a `Co-authored-by: Copilot` trailer — the same outcome as before the strip, because no AI edit sources are tracked any more. The `clear*` calls are fire-and-forget and now reject like the already-unregistered `_chat.editSessions.accept` call in the same file (the product accepted that shape in the chat-removal wave). No Git source was changed by this pass.
- **Gallery stays anonymous and functional; its statistics reporting is gone.** `IExtensionGalleryService.reportStatistic`, the `StatisticType` enum, the `ExtensionStatisticsUri` manifest resource/enum and the install/update/uninstall `extensionGallery:*` events are removed. Query, latest-version, resource-API and unpkg fallbacks, metadata reads, downloads/VSIX handling, signature assets, `X-Market-Search-Activity-Id` on downloads and the functional/absent-header set from pass 1 are unchanged. A focused test asserts the service exposes no `reportStatistic` and that a real download issues no `/stats` request.
- **`IExtension.telemetryData` and `IGalleryExtension.telemetryData` are gone** together with `getGalleryExtensionTelemetryData`/`getLocalExtensionTelemetryData`. The extension editor, install/runtime actions, recommendation surfaces and the extensions workbench service lost their events and `ITelemetryService` injections; their user-visible behavior (detail rendering, install/update/uninstall, recommendation notifications with their ignore-storage side effects, update checks, README rendering) is unchanged.
- **Remote connection health keeps its behavior, not its events.** `remoteConnectionLatencyMeasurer` and `getRoundTripTime` are retained because the remote indicator tooltip and the `vscode:getDiagnosticInfo` latency block read them; the `remoteConnectionLatency`/`remoteConnectionSuccess`/`remoteConnectionFailure`, `remoteConnectionHealth`, `remoteReconnection*`, `remoteConnectionLost`/`Gain` and `workbenchActionExecuted` producers are removed. Reconnection progress/dialog behavior, banner handling and the remote indicator state machine are unchanged.
- **Extension-host init no longer carries a logging-only telemetry flag.** `IEnvironment.isExtensionTelemetryLoggingOnly` and the three producers' `isLoggingOnly(productService, environmentService)` computation are removed; `platform/telemetry/common/telemetryUtils.ts#isLoggingOnly` is left in place as a consumer-less T1 residual. The `telemetryInfo` init block is retained because `vscode.env.machineId`/`sessionId`/`devDeviceId` (retained no-op facade) reads it.
- **Publisher trust and workspace-extension management are behavior-only.** The `extensions:trustPublisher` (trust/learn/cancel) and `workspaceextension:install`/`uninstall` events and both `ITelemetryService` injections are removed; the trust dialog, publisher trust persistence, workspace-extension add/remove and their storage are unchanged.

## Telemetry call-site pruning — pass-6 retained boundaries (U11, 2026-10-06)

- **Inert `--disable-telemetry` retained; `--telemetry-level`/`--disable-crash-reporter` are no longer recognized switches.** Both were removed from `platform/environment/{common,node}/argv.ts` (and `telemetry-level` also from `server/node/serverEnvironmentService.ts`; `disable-crash-reporter` also from the update-relaunch flag list). `src/vs/platform/environment/node/argvHelper.ts` still passes any unknown `--flag` through to Electron/Chromium and prints its ordinary `Warning: '<flag>' is not in the list of known options, but still passed to Electron/Chromium.` message, so an existing invocation with `--telemetry-level=off` keeps starting the product and now simply produces that warning instead of configuring anything. `--disable-telemetry` is unchanged and remains the documented inert invocation input.
- **The crash-reporter argv tail is deliberately not removed yet.** `crash-reporter-directory`/`crash-reporter-id` stay in the argv schema, `environmentService`, the desktop argv help and `server.cli.ts` because `scripts/test.sh`, `scripts/test.bat`, `scripts/test-remote-integration.*` and the azure-pipelines smoke steps still pass `--crash-reporter-directory`, and `scripts/**` is outside this assignment's edit surfaces. No crash reporter is started anywhere (`src/main.ts` is clean), so these keys are inert compatibility inputs today; their removal is recorded as a T8/T11 residual pending an edit-surface decision.
- **The retained TypeScript extension ships no reporter and no tracing.** `logTelemetry`/`logTraceEvent`, the `VSCodeTelemetryReporter`, the tsserver `telemetry` event handling and the `typescript.enableDiagnosticsTelemetry` switch are gone; TS language features, the ordinary tsserver error/exit logs and the `--enableTelemetry` tsserver launch argument (the TypeScript server's own protocol flag, not a Walker reporter) are unchanged.
- **The TAS experimentation adapter stays inert by design.** `extensions/typescript-language-features/src/experimentTelemetryReporter.ts` implements `tas.IExperimentationTelemetry` with no-op `setSharedProperty`/`postEvent`/`postEventObj` and is required by `vscode-tas-client`'s client shape, which already returns its telemetry-disabled service because `vscode.env.isTelemetryEnabled` is always false in this product. This is the documented `retained-compatibility` boundary for T9.
- **`virtualMachineHint` and the first-session date are retained with their real consumers** (developer perf view + diagnostics machine info; welcome-page first-session content). Recorded in `telemetry-inventory.md`/`deletion-review.md` as `retained-non-telemetry`, not as telemetry residue.
- **No new diagnostics were added while removing reports.** Where a telemetry branch had a real side effect (`doDownload` retry/log, extension-host crash recovery and bisect, missing-dependency prompts, signature verification logging, profile saving, welcome-page first-session decision) the side effect was kept and only the report removed; the one removed relay (`$logResolveTreeNodeFailure`) deleted an RPC method rather than replacing it with a log, because the extension host already logs and throws for the same failure.
- **Unchanged protected surfaces:** ordinary logs/notifications/errors, Git behavior, local profiles, anonymous Open VSX gallery functionality, `telemetry.feedback.enabled` + `platform/telemetry/common/telemetryService.ts`, the extension API compatibility shapes (`TelemetryLevel`/`TelemetryTrustedValue`/`env.machineId`/`sessionId`/`devDeviceId`) and `disable-telemetry`.

## Telemetry call-site pruning — pass-7 retained boundaries and behavior deltas (U11 T12 + crash-reporter tail, 2026-10-08)

- **The crash-reporter argv tail is now removed (supersedes the pass-6 note).** `--crash-reporter-directory` is gone from `scripts/test.bat`, `.vscode-test.js` and both `.vscode/launch.json` debug configs; `crash-reporter-directory`/`crash-reporter-id` are gone from `platform/environment/common/argv.ts`, the `environmentService` getters, `platform/environment/node/argv.ts` and the update-relaunch string/path lists; the dead `crash-reporter-id` and `enable-crash-reporter` desktop argv help entries and the `server.cli.ts` Windows-path validation are gone. An invocation that still passes `--crash-reporter-directory=…` now falls through to the ordinary `argvHelper` "not in the list of known options, but still passed to Electron/Chromium" warning (same as `--telemetry-level` from pass 6) and configures nothing. `--disable-telemetry` remains the documented inert input. The Electron test runners under `test/**` still use the switch for their own harness crash dumps; they are outside this assignment's edit surfaces and are recorded for the parent/V1.
- **The extension-host `telemetryInfo` init block is retained `retained-compatibility`.** `webWorkerExtensionHost`/`remoteExtensionHost`/`localProcessExtensionHost` still populate `telemetryInfo` (machine/session/device ids, first-session date, msftInternal) because the public `vscode.env.machineId`/`sessionId`/`devDeviceId`/`isNewAppInstall` facade reads it (`extHost.api.impl.ts`). The values come from the retained no-op `ITelemetryService`, so the facade keeps its shape while returning inert values. `TelemetryTrustedValue` stays re-exported on the `vscode` namespace for the same reason.
- **`ITelemetryData`/`ActionRunner.run(event, data)` and `DialogOptions.telemetryExtraData` are retained as inert parameters.** No producer builds a payload for them any more; the `workbench/browser/actions/workspaceActions.ts` overrides still declare the parameter. Recorded as a T3/T12 residual rather than removed, because the runner contract has callers across the workbench and no telemetry is emitted.
- **Prof-timers diagnostic line lost the telemetry session column.** The electron/browser `startupTimings` `[prof-timers]` output no longer includes `${telemetryService.sessionId}`; every other column (duration, product, commit, startup kind, perf baseline, heap statistics) is unchanged, and the unresponsive-sample fake error/log in `platform/profiling/common/profilingTelemetrySpec.ts` is retained as ordinary diagnostics while its `unresponsive.sample` payload is removed.
- **Survey URLs no longer carry the machine identifier.** The NPS and language-survey links drop the `&m=<machineId>` attribution parameter together with the `survey/...` and `survey/submit` events; the dialogs, storage keys, candidate selection and survey navigation are unchanged.
- **Telemetry-only modules were emptied, not replaced.** `browserViewTelemetry`, the `contrib/tags` tree, the bracket-pair-colorizer-2 contribution, `mergeEditor/browser/telemetry` and `inputLatencyContrib` are W46 parent-deletion candidates; their registrations/consumers are disconnected and no shadow/no-op replacement service was introduced.
- **No new diagnostics were added while removing reports.** Real side effects were kept (playwright code execution, browser view creation/context menus, diagnostics workspace stats callers, update download/relaunch, MCP install/elicitation/boot, onboarding tours, settings search, textMate tokenization, accessibility signals, speech sessions, profile creation); only the report was removed. Where a tracking map existed solely for an event (e.g. `mergeEditor` conflict counters, `speech` session counters, `agreement` sampling) it was removed with the event.
